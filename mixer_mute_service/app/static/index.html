API Reference

Addressing channels

Channels are addressed by their 1-based number in the URL path — channel 2 is /channels/2. Valid range is 1...max_channels (set in config.yaml). An out-of-range number returns 400 invalid channel.

Every action only sends to the mixer if the channel is safe — i.e. the service has observed a valid fader value and the mixer link is live. Otherwise it is blocked with a reason (the fader is never moved to a guessed position).

Status endpoints
EndpointDescription
GET /health Service + connection status: enabled, mixer_connected, last_update_age_seconds.
GET /state All channels with fader_hex, ages, muted, and safe.
GET /channels/{n} State for a single channel.
Channel control
EndpointDescription
POST /channels/{n}/mute Mute channel n. Reuses the last observed fader value (never guesses).
POST /channels/{n}/unmute Unmute channel n. Reuses the last observed fader value.
POST /channels/{n}/fader Move the fader. Body: {"value": 750} — position 0 (−∞) to 1000 (top), about 750 = 0 dB. Keeps the current mute state; blocked if that state is unknown.
POST /channels/{n}/recall-fader Same, with a stored fader value as hex. Body: {"fader_hex": "00803b44"}. Used by the Use / Use All buttons.
curl -X POST http://localhost:8765/channels/2/mute
curl -X POST http://localhost:8765/channels/2/unmute
curl -X POST http://localhost:8765/channels/2/fader \
  -H 'Content-Type: application/json' \
  -d '{"value":750}'
Group control (backend API)

Groups are managed via API and persisted in groups.json. The API remains fully functional for Stream Deck or other HTTP clients.

EndpointDescription
GET /groups List all groups and their channels.
POST /groups Create a group. Body: {"name": "...", "channels": [..]}
GET /groups/{name} A single group's channels.
POST /groups/{name}/update Replace a group's channels. Body: {"channels": [..]}
POST /groups/{name}/delete Delete a group.
PUT /groups/{name} Legacy alias for group update.
DELETE /groups/{name} Legacy alias for group deletion.
POST /groups/{name}/mute Mute every channel in the group (all-or-nothing).
POST /groups/{name}/unmute Unmute every channel in the group.
POST /groups/{name}/toggle Unmute if all channels are muted, otherwise mute.
curl -X POST http://localhost:8765/groups/drums/toggle
curl -X POST http://localhost:8765/groups \
  -H 'Content-Type: application/json' \
  -d '{"name":"horns","channels":[5,6,7]}'
curl -X POST http://localhost:8765/groups/horns/update \\
  -H 'Content-Type: application/json' \\
  -d '{"channels":[5,6]}'
curl -X POST http://localhost:8765/groups/horns/delete
Panic (disable / enable sending)
EndpointDescription
POST /panic/disable Block all sends immediately. State tracking keeps running.
POST /panic/enable Re-enable sending.
Responses & status codes

Successful sends return 200:

{"ok": true, "channel": 2, "target_muted": true,
 "fader_hex": "1f14b643", "sent_hex": "5a5a..."}

Blocked requests carry a clear reason:

  • 400 — invalid channel number or fader_hex
  • 404 — unknown group
  • 409 — unsafe: no mixer link, stale/unknown fader, service disabled (panic), or group with an unsafe channel
{"ok": false, "channel": 2, "reason": "no fader value known"}

{"ok": false, "group": "drums", "reason": "unsafe group operation",
 "details": [{"channel": 4, "reason": "no fader value known"}]}
